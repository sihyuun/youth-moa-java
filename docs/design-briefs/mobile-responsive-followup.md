## 2. Claude Design 다음 이터레이션 보완 요청 (6건)

### F1. 인증 상태 헤더 — 알림 뱃지 시각 규격

**현황**: §2.1 에서 알림 종 드롭다운을 `/notifications` 페이지 이동으로 승격. 이때 종 아이콘 자체는 유지되지만 `.header-bell-dot` (안읽음 뱃지) 의 모바일 위치·크기 명시 없음.

**요청 사항**:
- 종 버튼 44×44 안에서 뱃지 위치 (현재 데스크톱은 아이콘 우상단 오프셋)
- 안읽음 개수 표시 여부 (숫자 뱃지 vs 단순 dot)
- 개수 10+ 표기 규칙 ("99+" 등)

### F2. 탭바 활성 상태 판정 규칙

**현황**: 탭바 4항목이 루트 4화면 (`/`, `/programs`, `/centers`, `/mypage`) 에만 렌더된다고 명시. 그런데 파생 경로에서 어느 탭 active 인지 규칙이 없음.

**요청 사항**:
- `/programs/{id}` 상세 (탭바 자체가 렌더 안 됨) 에서 back 이동 시 어느 탭으로 복귀?
- `/mypage?tab=favorites` 등 쿼리 파라미터 화면에서 "마이" 탭 active 처리 여부
- `/search` (검색) 에서 어느 탭도 active 아닌 상태 허용? 아니면 유지된 이전 탭?

### F3. 드로어 상태 전환 — 인증 변화 시 UX

**현황**: §2.2 에서 비인증 시 유저 블록을 `[로그인] [회원가입]` 버튼으로 대체. 그러나 세션 만료·로그아웃 후 재열림 시 전환 명시 없음.

**요청 사항**:
- 드로어 열린 상태에서 로그아웃 실행 → 드로어 닫음 vs 유저 블록 즉시 갱신
- 드로어 안에서 로그인 페이지 이동 → 드로어 자동 닫힘 여부

### F4. 캐러셀 스크롤 인디케이터

**현황**: 홈 프로그램 236px · 공간 200×150 · 관련 프로그램 180 등 가로 스크롤 도입. 사용자가 옆 카드 존재를 인지할 시각 힌트 없음.

**요청 사항**:
- Peek (다음 카드 12~16px 노출) vs Dot 인디케이터 vs Arrow (좌우 그라디언트)
- 스크롤 위치별 상태 (첫/중간/끝) 시각 변화
- 시안 카드 `1b` `1d` 에서 peek 이 이미 반영됐다면 개발 가이드에도 명시 필요 (현재 CSS `flex: 0 0 236px` 만 있어 padding 어떻게 배치해 peek 만드는지 불명확)

### F5. 바텀시트 swipe-to-dismiss

**현황**: `.filter-popover` 등 시트가 backdrop 클릭·ESC 로만 닫힘. 모바일 관용 UX (아래로 드래그) 없음.

**요청 사항**:
- Swipe-down 임계값 (예: 100px 이상 드래그 시 닫음)
- 드래그 중 시트 위치·backdrop opacity 연동
- 미탑재 결정 시 사유 명시 (예: 학습 프로젝트 스코프 축소)

### F6. 가로 스크롤 pill 스크롤 위치 복원

**현황**: 필터·탭 pill 이 가로 스크롤. 상태 변경 후 (예: 상태 pill "모집중" 선택 → 필터 변경 후 재진입) 스크롤 위치 재현 여부 불명.

**요청 사항**:
- 활성 pill 이 항상 뷰포트 안에 오도록 auto-scroll into view 정책
- HTMX 부분 갱신 시 스크롤 위치 유지 방식 (sessionStorage vs `scroll-behavior`)

## 4. 이식 작업 프로세스

### 4.1 PR 분할·순서

가이드 §7 P0~P10 그대로 채택. 매 PR 종결 조건:

1. `@media (max-width:767px)` 안에만 규칙 추가 (grep 로 확인)
2. 데스크톱 계약 (`--project=contracts`) 갭 0 유지
3. 모바일 spec (`*-mobile.spec.ts`) 신설 · 375×812 assertion 통과
4. 사용자 시각 검증 (스크린샷 375 · 768 · 1440 각 첨부)
5. ym-verify 적대적 검증 → GO 판정

### 4.2 검증 3분리 (매 PR)

```
## 정적 검증
- compileJava · CSS 파싱 · Thymeleaf 렌더 (RenderTest)

## 동적 검증
- 3 뷰포트 (375·768·1440) 각 curl + HTML 마크업 grep

## 인터랙션 검증
- Playwright chromium 스펙 (신규 mobile spec + 기존 desktop 회귀 유지)
- 드로어/시트/캐러셀 클릭·swipe 인터랙션

## 시각 확인
- 사용자 시각 검증 (매 PR)
```

### 4.3 사고 재발 방지 (CLAUDE.md 조항 준수)

- **모바일 media 안에서만 작성** — desktop 계약 P0 위반 방지
- **fragment 이름 충돌** — HTML 태그명 (nav·drawer 등) 을 fragment 이름으로 사용 금지 (`sidebar` `mobileRelated` 처럼 별칭)
- **HTMX 함정** — 드로어·시트 안에서 `hx-swap` 사용 시 중복 ID·204 no-swap·`th:if + th:replace` 병치 재확인
- **CSS source-order** — 새 rule 추가 전 grep 로 동일 selector 후행 정의 여부 확인

### 4.4 각 PR 브랜치·커밋 규약

```
feature/mobile-P0-boundary-tokens
feature/mobile-P1-shell (헤더/드로어/탭바/푸터)
feature/mobile-P2-home
...
```

커밋 메시지 형식 (기존 컨벤션 준수):
```
YYMMDD_mobile_<범위> - 요약

- CSS media query (@media max-width:767px) N줄 추가
- 마크업 변경 M건 (fragment 신설·햄버거 등)
- E2E spec `*-mobile.spec.ts` K건 통과
- 데스크톱 계약 갭 0 유지 확인
```
