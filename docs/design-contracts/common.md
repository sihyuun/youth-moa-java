# 디자인 계약 — 공통 헤더 · 푸터

> **추출 기준**: `docs/00_assets/prototype.tsx` L402~464 (`Header`) / L467~496 (`Footer`) / L368~377 (`Avatar`) / L380~399 (`UserMenuPanel`) / L322~364 (`NotifPanel`) / L10~21 (토큰 `T`) — 2026-07-28
> **검증 상태**: 테스트 연결됨 (`e2e/tests/visual-common.spec.ts`) · 스크린샷 baseline 미등록
> **기계 계약**: `e2e/contracts/common.ts` — px·색·폰트·개수·라벨은 전부 그쪽에서 자동 검사된다. 이 문서는 **판단이 필요한 구조**만 담는다.

헤더·푸터는 13개 사용자 대면 화면 **전부**에 렌더된다. 여기 갭 1건은 화면별 갭 13건과 같은 무게를 갖는다. 그래서 화면 계약 확산에서 우선순위 1번이다.

## 1. 왜 계약이 2개인가 — 헤더의 두 벌 규격

`Header` 는 단일 컴포넌트지만 **시각 규격을 두 벌** 갖는다 (proto L406).

```
transparent = isHome && !scrolled
```

| | transparent 모드 | 일반 모드 |
|---|---|---|
| 관측 경로 | `/` 최상단 (스크롤 0) | `/programs` 등 나머지 12개 화면 + 홈 스크롤 후 |
| 배경 | `transparent` | `surface` (#fff) |
| 하단 보더 | 없음 | 1px `T.border` |
| 그림자 | 없음 | `0 1px 8px rgba(0,0,0,0.06)` |
| 전경색 `fg` | `#fff` | `T.text` |
| 보조 전경색 `fgSec` | `rgba(255,255,255,0.85)` | `T.textSec` |
| 로고 심볼 | `filter: brightness(0) invert(1)` | 원본 |
| 아바타 배경 | `rgba(255,255,255,0.25)` | `T.primaryLight` |
| proto | L406~408 / L415~459 | 동일 |

기계 계약도 이 분리를 그대로 따른다.

| 계약 | 경로 | 담는 것 |
|---|---|---|
| `commonContract` | `/programs` | 일반 모드 헤더 전체 + 드롭다운 패널 + 푸터 |
| `commonHomeContract` | `/` | transparent 모드 색상 규격만 |

`/programs` 를 기본 경로로 고른 이유: transparent 분기는 홈 전용이므로 **12개 화면이 공유하는 규격**을 관측하려면 홈이 아니어야 하고, 동시에 활성 네비(`active`) 표식도 검사할 수 있어야 한다.

## 2. 헤더 레이아웃 — 3분할 대칭

```
[ 로고 (flex:1) ] [ nav (고정폭, gap 36) ] [ 우측 액션 (flex:1, justify-end) ]
```

좌·우 블록이 **둘 다 `flex:1`** 이기 때문에 nav 가 뷰포트 정중앙에 고정된다 (proto L417 / L424 / L430). 우측 액션이 늘어나도(로그인 시 종·아바타·이름 추가) nav 는 움직이지 않아야 한다 — 이 대칭이 깨지면 로그인 전후로 nav 가 좌우로 흔들린다.

높이 68 (`T.headerH`), 좌우 패딩 80 은 푸터·본문 `--content-px` 와 같은 값이다.

## 3. 네비게이션 정보구조 (카피 예외 아님)

서비스명·마케팅 문구는 카피 이탈로 다루지만, **네비 항목명과 개수는 정보구조**이므로 계약에 정식 포함한다.

| # | 라벨 | 목적지 | proto |
|---|---|---|---|
| 1 | 프로그램 | `/programs` | L410 |
| 2 | 청년센터 | `/centers` | L411 |
| 3 | 공지사항 | `/notices` | L412 |

- 홈(`/`)은 nav 배열에 없다 → 홈에서는 활성 항목이 0개여야 한다 (로고 클릭이 홈 진입 경로).
- 활성 표식은 **weight 600 + primary 색 + 하단 2px 언더라인** 3가지가 동시에 적용된다. transparent 모드에서는 셋 다 흰색으로 치환.
- 마이페이지·알림 전체보기는 nav 가 아니라 **우측 액션 드롭다운 안**에 있다. nav 에 추가하면 안 된다.

## 4. 우측 액션 — 로그인 상태 분기

| | 비로그인 | 로그인 |
|---|---|---|
| 검색 | 아이콘 20 (공통) | 아이콘 20 (공통) |
| 알림 | 없음 | 종 아이콘 20 + 미읽음 dot 7 |
| 계정 | 로그인 아이콘 **21** (텍스트 버튼 아님) | 아바타 30 + `{이름}님` + chevron 14 |
| proto | L459 | L432~457 |

- 검색 20 / 로그인 21 은 **의도적으로 1px 다르다** (proto L431 vs L459). 같은 값으로 맞추면 갭.
- 비로그인 계정 영역은 "로그인 / 회원가입" 텍스트 버튼이 아니라 **아이콘 1개**다. 회원가입은 로그인 화면 안에서 진입한다.
- 로그인 시 헤더에 사람 이름이 노출되므로, `<sec:authentication>` element 태그 리터럴 렌더 사고(CLAUDE.md Thymeleaf 규칙, 2026-07-03)가 재발하면 이름이 통째로 사라진다. 기계 계약에 `header.user.name.notEmpty` (`:not(:empty)`) + `header.user.name.text` (시드 유저 기준 `시드유저1님`) 2단으로 걸어 두었다.

## 6. 푸터 구조 (proto L467~496)

```
[ 로고 (28px 심볼 + 워드마크 16) ] ─40─ [ 중앙 (flex:1) ] ─40─ [ SNS 4개 (24px) ]
```

## 7. 기계 계약이 커버하지 않는 항목

자동 검사 대상이 아니므로 화면 작업 시 **사람이 확인**한다.

### 7-1. 스크롤 전환 (홈 전용)

- 임계값 **60px** — prototype 은 `.scroll-container` 의 `scrollTop > 60` (proto L2713), 구현은 `window.scrollY > 60` (`static/js/header-scroll.js`). 값은 일치.
- 전환은 `background 300ms ease, border-color 300ms ease, box-shadow 300ms ease` (proto L415). 로고 심볼 `filter` 와 텍스트 `color` 도 300ms (proto L419~420).
- **확인 포인트**: 홈에서 천천히 스크롤할 때 배경·보더·그림자·로고색·네비색이 **동시에** 전환되는지. 하나만 즉시 바뀌면 transition 누락.

### 7-2. 드롭다운 열림·닫힘 동작

- 열림 애니메이션 `dropdown-enter` 180ms ease — prototype 은 `translateY(-8px) → 0`, 구현은 `-4px → 0`. 이동량만 다름 (`prototype.html` L18 vs `main.css` L406~410).
- 종·아바타 상호 배타 토글 (§5 상태 머신).
- 바깥 클릭 / ESC 로 닫힘 → ESC 시 트리거로 포커스 복귀 (`main.css` L270~274 주석).
- 알림 패널 액션 (`모두 읽음`, `모두 지우기`, 항목별 삭제) 클릭 후 패널이 **닫히지 않고 그 자리에서 갱신**되는지.

### 7-3. hover

| 요소 | prototype | 현재 구현 |
|---|---|---|
| 네비 링크 | `opacity: 0.8` (`.nav-link:hover`) | `color: primary` |
| 드롭다운 행·링크 (`btn-hover`) | `filter: brightness(0.92) + translateY(-1px)`, active 시 `scale(0.97)` | 행 배경 `primary-bg` 전환 |
| 푸터 링크 | 없음 (cursor 만) | `color: primary` |

전부 "다름"이지만 **어느 쪽이 옳은지는 판단 영역**이라 계약에 넣지 않았다. 구현 쪽 hover 가 웹 관례에 더 가깝다는 판단이면 그대로 두면 된다.

### 7-4. 그 외

- 로고 심볼 `brightness(0) invert(1)` 필터가 실제로 흰색으로 보이는지 (PNG alpha 에 따라 결과가 달라짐).
- 미읽음 dot 이 종 아이콘 획과 겹치지 않는지 (top/right `-2` 는 아이콘 **밖으로** 밀어내는 값).
- 알림 항목 제목·본문의 1줄 말줄임(`text-overflow: ellipsis`) 이 실제 긴 문자열에서 동작하는지.

## 8. 현재 갭 (2026-07-28 계약 검사 결과)

`e2e/gap-reports/gap-common.md` · `gap-common-home.md` 참조.

| 계약 | 결과 |
|---|---|
| `commonContract` (`/programs`) | **96/116 통과 · 갭 20건** (P0 0 / P1 5 / P2 15) · 의도적 이탈 1건 |
| `commonHomeContract` (`/`) | **16/16 통과 · 갭 0건** |

**P0 갭 0건** — 헤더 3분할 대칭, 네비 3항목, 로그인 상태 분기, 헤더 사용자 이름 렌더, transparent 모드 색상 규격은 전부 prototype 과 일치한다. 아키텍처 차원의 사고는 없다.

### 무거운 갭 순

1. **P1 — 푸터 `관리자` 링크·구분선 누락** (링크 4개 기대 / 실제 3개). admin 트랙의 유일한 진입점이 전 화면에서 빠져 있다. `footer.links.count` `footer.links.admin` `footer.links.divider`
2. **P1 — 알림 항목 원형 아이콘이 빈 원** (`.notif-icon svg` 기대 존재 / 실제 없음). prototype 은 알림 종류별 lucide SVG (bell·calendar·close) 를 원 안에 넣어 유형을 구분한다. 현재는 색만 다른 회색·보라 원이라 유형 정보가 소실. CLAUDE.md "SVG 를 다른 것으로 대체 금지" 규칙과 같은 계열.
3. **P1 — 알림 패널 액션 2개 중 1개 누락** (`모두 지우기` + `|` 구분자). 현재는 `모두 읽음` 만 있다.
4. **P1 — 알림 항목별 삭제(x) 버튼 누락**. 개별 알림 제거 경로가 없어 목록이 계속 쌓인다.
5. **P2 — 그림자 2건이 브랜드 틴트 토큰으로 대체됨**
   - 헤더: 기대 `rgba(0,0,0,0.06) 0 1px 8px` / 실제 `rgba(63,48,233,0.06) 0 1px 3px` (`--shadow-sm`)
   - 알림 패널: 기대 `rgba(0,0,0,0.14) 0 12px 40px` / 실제 `rgba(63,48,233,0.09) 0 10px 24px` (`--shadow-lg`)
   프로토타입은 이 두 곳만 **중립 검정 그림자**를 쓴다. 토큰을 그대로 적용하면서 발생.
6. **P2 — 유저 드롭다운 프로필 카드가 전반적으로 한 치수 작음**: 아바타 38→36, 이름 15→14, 패딩 16→14, gap 10→12(오히려 큼), 패널 폭 220 고정 → `min-width:240` + auto.
7. **P2 — 미읽음 dot 위치·테두리**: top/right `-2px` → `0px` (아이콘 안쪽에 붙음), 테두리 1.5px → 1px.
8. **P2 — 푸터 치수**: 블록 간격 40→24, 하단 패딩 16→20, 링크 폰트 11→12.

## 9. 사용자 결정 필요

계약과 구현이 다르지만 **의도적 이탈일 수 있는** 항목. 확정되면 계약의 `deviation` 필드에 사유를 넣어 검사에서 제외한다.

| # | 항목 | prototype | 현재 | 논점 |
|---|---|---|---|---|
| ~~Q1~~ | ~~헤더 고정 방식~~ | **철회 (2026-07-28) — 오판이었음.** prototype 도 sticky 다: `Header` 함수 본문은 `position:'relative'`(L415) 지만 `App` 이 L2715 에서 `position:'sticky', top:0, zIndex:200` 래퍼로 감싸고 `onScroll` 로 `scrollTop>60` 에서 `scrolled` 를 켠다. 구현과 정합이므로 결정할 것이 없다. 홈 hero 의 `margin-top: calc(-1 * var(--header-h))` 도 그래서 맞다 | | 컴포넌트 본문만 읽고 레이아웃을 판정하면 상위 래퍼 속성을 놓친다 → `POLICY.md` 「관련 ADR」 절에 교훈 기록 |
| Q2 | 그림자 정책 | 헤더·알림 패널만 중립 검정 그림자 | 전역 `--shadow-*` 브랜드 틴트 토큰 적용 | 디자인 시스템 일관성(토큰 우선) vs prototype 재현. 토큰 유지로 결정하면 P2 갭 2건이 `deviation` 처리되어 갭 18건 |
| Q3 | 푸터 `관리자` 링크 | 있음 (→ `forbidden`) | 없음 | admin 트랙 착수 전까지 **의도적 미노출**인지, 단순 누락인지. 미노출이면 `deviation`, 누락이면 P1 티켓 |
| Q4 | 알림 `모두 지우기` · 항목 삭제 | 있음 | 없음 | 알림 하드 삭제는 백엔드 API 신설이 필요하다. "읽음 처리만 제공" 이 정책이면 `deviation`, 아니면 후속 티켓 |
| Q5 | 푸터 링크 폰트 11 | 11 | 12 | 11px 는 접근성상 작다는 판단으로 올렸을 수 있음. 의도면 `deviation` |
| Q6 | hover 규격 (§7-3) | `opacity 0.8` / `brightness(0.92)+translateY` | `color: primary` / 배경 전환 | 기계 검사 불가 영역. 현행 유지가 웹 관례에 가깝다고 보면 이 문서 기록만으로 종결 |

Q2·Q3·Q5 를 "현행 유지" 로 결정하시면 갭은 20건 → **15건** (P1 3 / P2 12) 이 됩니다.
