# 전 화면 공통 디자인 정책

> 확정일 2026-07-28. 갭 수정 PR 은 본 문서의 **항목 번호(P-1 등)를 인용**한다.

## 이 문서의 범위 — 좁게 유지할 것

**편입 기준: 이 결정이 2개 이상 화면의 계약에 영향을 주는가?**

- **예** → 여기에 적는다
- **아니오** → 해당 화면의 `docs/design-contracts/<screen>.md` 마지막 절에 적는다
- **아키텍처 성격** (프레임·라우팅·상태 관리 방식) → `docs/adr/` 에 ADR 로 적는다

이 프로젝트는 결정이 이미 6군데(`docs/adr/`, `docs/specs/*.md`, 계약 `.md`, 계약 `.ts` 의 `deviation`, `CLAUDE.md`, `docs/STATE.md`)에 흩어져 있다. "모든 결정" 을 담는 문서를 하나 더 만들면 중복이 생기고, 중복되면 둘 중 하나가 낡아 **어느 쪽이 진리인지 알 수 없게 된다.** 그래서 이 문서는 의도적으로 얇게 유지한다.

## 강제력은 문서가 아니라 계약 필드에 있다

문서는 **왜**(근거)를, 계약은 **무엇**(기대값·제외 여부)을 담는다. 산문 규칙은 지켜지지 않는다는 것이 이미 확인됐다 — P-3(SVG) 은 2026-07-09 부터 `CLAUDE.md` 에 명문화돼 있었는데도 7/28 계약 검사에서 위반 3건이 발견됐다.

| 계약 필드 | 의미 | 리포트 |
|---|---|---|
| `deviation: '...'` | prototype 을 **영구히** 안 맞춤 | "의도적 이탈" 절 |
| `deferred: '<티켓 경로>'` | 맞출 예정이나 **이번 범위 아님** | "이월" 절 |
| (없음) | 맞춰야 함 | 갭으로 집계 |

**구현이 계약과 다르다고 계약 기대값을 구현에 맞춰 고치면 장치 전체가 무의미해진다.** 반드시 위 두 필드 중 하나로 처리한다.

## P-1. 카피(문구)는 구현 현행 유지

**결정**: prototype 의 카피와 구현이 다르면 **구현을 따른다.** 계약에는 prototype 값을 남기되 `deviation` 으로 검사 제외.

**근거**: 서비스명이 「청년모아」로 정착했고, prototype 은 "경기도 청년센터" 를 전제로 한 초기 카피를 쓴다. 지역 한정 카피로 되돌리는 것은 브랜드 후퇴다.

**적용 예**: 홈 Hero 타이틀·설명, 프로그램 목록 빈 상태 카피, 상세 sticky 상태 줄.

**예외**: **정보구조는 카피가 아니다.** 네비게이션 메뉴 항목명·개수, 상태 탭 라벨(`모집중`·`진행예정`·`종료`), 정렬 옵션 라벨은 화면 동작·정보 계층을 규정하므로 계약에 정식으로 넣고 맞춘다.

## P-2. 그림자는 브랜드 틴트 토큰 유지

**결정**: `--shadow-sm/-md/-lg` (인디고 틴트 `rgba(63,48,233,...)`) 를 그대로 쓴다. prototype 이 중립 검정 그림자를 쓰는 곳도 토큰을 따른다. `deviation` 처리.

**근거**: prototype 은 헤더·알림 패널 두 곳만 중립 검정(`rgba(0,0,0,0.06)`, `rgba(0,0,0,0.14)`)을 쓰고 나머지는 브랜드 틴트다. 두 곳만 예외를 두면 토큰 체계에 구멍이 생기고, 새 컴포넌트마다 "여긴 어느 쪽?" 판단이 필요해진다. 일관성이 미세한 톤 차이보다 가치가 크다.

**적용 예**: 헤더 그림자, 알림 패널 그림자.

**주의**: 그림자 **크기·확산**(`0 1px 3px` vs `0 12px 40px`)은 위계를 나타내므로 정책 대상이 아니다. 토큰 중 적절한 단계를 골라 맞춘다.

## P-3. 아이콘은 SVG — 문자·이모지 대체 금지

**결정**: prototype 이 lucide `Icon` 을 쓰는 자리는 `templates/fragments/icons.html` 의 SVG fragment 를 쓴다. 문자(`✓` `▾` `⚠` `×` `📍`)로 대체하지 않는다. **이탈 불가 — deviation 대상이 아니다.**

**근거**: 폰트별 렌더 편차, 색·크기 제어 불가, 아이콘 의미 오선택(prototype 이 `user` 인 곳에 `📞` 를 쓰는 등). 2026-07-09 F0h 사고로 규칙화됐다.

**현재 위반 3건** (7/28 계약 검사): Stats 아이콘 `✓`, 지역 드롭다운 chevron `▾`, 상세 경고 `⚠`.

**적용 방법**: 아이콘이 없으면 prototype 의 `Icon` 정의부(`prototype.tsx` L57~83)에서 path 를 그대로 이식해 `icons.html` 에 fragment 를 추가한다. 아이콘 **종류**도 prototype 명시값을 따른다("전화니까 phone" 같은 임의 판단 금지).

## P-4. 폭 토큰을 전역값으로 일괄 적용하지 않는다

**결정**: `--content-max`(1440) 는 **기본값일 뿐 모든 섹션의 정답이 아니다.** prototype 이 특정 블록에 별도 `maxWidth` 를 준 곳은 그 값을 따른다.

**근거**: 2026-07-27 batch2·batch3 이 `.container` 정책을 기계적으로 적용해 폭 갭이 발생했다. prototype 은 대부분 섹션을 전폭+80px 패딩으로 두고 **특정 블록만 의도적으로 좁힌다** — 그 비대칭이 시각 리듬을 만든다.

**확인된 예외값**: 홈 퀵메뉴 1080 · 프로그램 목록 컨테이너 1160 · 상세 본문 1000 · 상세 sticky 바 1080.

**적용 방법**: 새 섹션 작업 시 `.container` 를 붙이기 전에 prototype 해당 블록의 `maxWidth` 를 먼저 확인한다.

## P-5. prototype 에 없는 개선은 계약에 넣지 않고 문서로 남긴다

**결정**: 구현이 prototype 보다 나은 방향으로 추가한 요소는 **계약 검사 대상이 아니다.** 계약은 "prototype 대비 누락·불일치" 를 잡는 도구이므로, 추가분을 넣으면 방향이 뒤집힌다. 대신 해당 화면 계약 `.md` 에 "prototype 에 없는 구현 추가 요소" 로 기록해 나중에 "이건 왜 있지?" 가 되지 않게 한다.

**적용 예**: 비밀번호 눈 아이콘 토글, 활성 필터 칩 줄(`.active-filter-bar`), 지도 클러스터링·내 위치·공유, 드롭다운 취소/적용 푸터.

**주의**: 추가 요소가 prototype 요소를 **대체**한 경우는 단순 추가가 아니므로 해당 화면 Q 항목으로 올려 결정한다.

**선례 (2026-07-28)**: 프로그램 목록 필터 드롭다운. 구현이 헤더(제목·×)와 취소/적용 푸터를 두어 prototype 의 "체크 즉시 반영" 을 대체했다 → Q 로 올려 **prototype 대로 맞추기로 확정**(갭 유지, `deviation` 아님). 판단 근거와 구현 주의사항은 [programs.md §10-A](programs.md). 대체형인지 단순 추가인지 헷갈릴 때 이 사례를 참고한다 — 기준은 **"prototype 의 어떤 동작이 이것 때문에 불가능해졌는가?"** 이고, 답이 있으면 대체형이다.

## 관련 ADR

현재 없음. 아키텍처 성격의 이탈이 확정되면 `docs/adr/` 에 ADR 을 추가하고 여기에 링크한다.

> **정정 (2026-07-28)**: 초기 검토에서 "헤더가 prototype 은 `relative` 인데 구현은 `sticky` 라 아키텍처 이탈" 로 판단해 ADR 신설을 검토했으나, **오판이었다.** `Header` 컴포넌트 자체는 `position:'relative'`(`prototype.tsx` L415)지만 `App` 이 L2715 에서 `position:'sticky', top:0, zIndex:200` 래퍼로 감싸고 `onScroll` 로 `scrollTop>60` 에서 `scrolled` 를 켠다. 구현과 **정합**이므로 이탈이 아니다.
>
> 교훈: 컴포넌트 함수 본문만 읽고 레이아웃 판정을 내리면 **상위 래퍼가 부여하는 속성을 놓친다.** `position`·`overflow`·`maxWidth` 는 조상 요소가 결정하는 경우가 많으므로 `App`(`prototype.tsx` L2650~2733)까지 확인한다.
