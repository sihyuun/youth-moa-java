## 0. 상태 슬롯 매핑 (이 화면 고유)

runner 의 상태 슬롯은 원래 로그인 여부용이지만, **이 화면의 시각 분기는 로그인 여부가 아니라 프로그램 상태**다. prototype 의 `isLoggedIn` 은 클릭 동작만 바꾸고 렌더 결과를 바꾸지 않는다 (L1013 즐겨찾기, L1029 CTA — 둘 다 비로그인이면 `onLoginClick()` 만 호출). 그래서 슬롯을 아래처럼 재배정했다.

| 슬롯 | 리포트 머리글 | 실제 대상 |
|---|---|---|
| `anon` | 비로그인 | 모집중(OPEN) 프로그램 `/programs/1` · 비로그인 |
| `auth` | 로그인 | 종료(ENDED) 프로그램 `/programs/4` · 로그인 |

진행예정(UPCOMING `/programs/5`)·운영중단(SUSPENDED `/programs/9`)·정원마감(full) 은 슬롯이 없어 아래 §2 상태표로만 관리한다.

## 5. 기계 계약이 커버하지 않는 항목

자동 검사 대상이 아니므로 화면 작업 시 **사람이 확인**한다.

- **WaitlistModal 부재** (L265~321, L1068) — 오픈/빈자리 알림 신청 모달이 구현에 아예 없다. 440px 카드, `bell` 아이콘 원형 56, 알림 수단 2개(카카오 알림톡·이메일) 체크 카드, `취소`/`알림 받기` 2버튼, 신청 후 `신청 완료` 로 라벨 전환 + 1.1초 후 자동 닫힘. 이게 없으면 진행예정·정원마감 CTA 가 동작할 곳이 없다
- **알림 신청됨 토글** (`notified` state, L1029·L1114) — 재클릭 시 해제 + 토스트
- **정원마감(full) 분기 자체가 구현에 없음** — `detail.html` 의 CTA 는 `program.status`(OPEN/UPCOMING/ENDED/SUSPENDED) 로만 분기한다. 정원이 찬 OPEN 프로그램도 `신청하기` 가 그대로 노출된다. 모집 상태 카드(`ProgramCardDto`)는 `모집 마감` 헤드라인을 이미 계산하고 있어 **카드 문구와 CTA 가 서로 모순**된다
- **하단 sticky 바 상태 줄의 정보량** (L1099) — prototype 은 `마감까지 3일 · 27/30명`, 구현은 상태 라벨(`모집중`)만. 카피 유지 결정과는 별개로 D-day·신청 인원이 빠져 있다
- 신청 기간 값 포맷 (L995) — prototype `2026-07-01 ~ 07-31`, 구현 `~ 2026.08.01 까지`
- 이미지 로테이션 없음 (상세는 단일 이미지 `IMGS.pg[0]`) — 홈과 달리 크로스페이드 없음
- 카드·버튼 hover (`btn-hover`), 토스트 (`addToast`), 진행 장소 모달의 격자 배경·핀 회전 연출 (L1074~1078)
- 즐겨찾기 비로그인 클릭 시 prototype 은 **로그인 모달**, 구현은 `/login` **페이지 이동**

## 6. 현재 갭 (2026-07-28 계약 검사 결과)

`e2e/gap-reports/gap-program-detail.md` 참조. **90/101 통과 · 갭 11건** (P0 0 / P1 6 / P2 5) · 의도적 이탈 1건.

무거운 것부터:

1. **P1 — 하단 sticky 바 내부 폭 1440** (계약 1080). batch2 가 `--content-max` 를 그대로 써서, 본문 1000 폭과 어긋난 채 CTA 가 화면 양끝으로 벌어진다. 이 화면에서 폭 불일치가 가장 눈에 띄는 항목
2. **P1 — CTA 아이콘 3종 전부 누락** — 본문 모집중 CTA `check`(L1030), sticky CTA `check`/`search`(L1106·L1115). 종료 상태의 **본문** CTA 만 `search` SVG 가 있고 나머지는 텍스트만
3. **P1 — 지원 대상 경고 아이콘이 문자 `⚠`** (L1057 은 lucide `bell` SVG). CLAUDE.md "prototype 이 SVG 인 곳에 이모지 대체 금지" 규칙 위반이 남아 있음
4. **P1 — 모집 상태 카드 radius 8** (계약 12 = `T.radius`). `--radius-md` 를 쓴 것이 원인. 같은 화면의 정보 카드·경고 박스는 12 라 카드끼리 모서리가 안 맞는다
5. **P2 — 종료 프로그램 bar 색이 `textTri`** (계약 `T.border`). 종료 표현이 필요 이상으로 진하다

## 7. batch2 재작업 판정

2026-07-27 batch2 가 손댄 항목은 **대부분 prototype 과 일치**한다. 88개 검사 중 80개 통과, P0 갭 0건.

| batch2 작업 | 판정 | 근거 |
|---|---|---|
| sticky 하단 CTA 바 신설 | ⚠️ 부분 일치 | position/bg/blur/z-index/버튼 치수(200x48, radius 12, 16/700) 전부 일치. **내부 폭만 1080 → 1440 오차**, 아이콘 누락 |
| 정보 그리드 2열 | ✅ 일치 | 5항목·gap 10·패딩 14/16·radius 12·아이콘 34/radius 9·라벨 12·값 13.5 전부 통과 |
| 뒤로가기 아이콘 38x38 | ✅ 일치 | 38x38·radius 9·marginBottom 24·SVG 모두 통과 |
| 본문 컨테이너 1000 | ✅ 일치 | 폭 1000·패딩 36/48 통과 |
| 종료 상태 시각 처리 | ✅ 거의 일치 | grayscale 필터·오버레이·칩 텍스트/배경 통과. bar 색·테두리 두께만 미세 편차 |
| 모집 상태 카드 | ⚠️ 부분 일치 | 폰트·바·subtext 는 일치, **radius 만 8** |
| 지원 대상 3카드 | ✅ 일치 | 개수·gap 12·아이콘 36·값 14 통과. 경고 **아이콘만** 문자 |

**결론**: batch2 의 치수 이식은 정확했고, 남은 갭은 (a) 폭 토큰을 전역 `--content-max` 로 잡은 1건, (b) 아이콘 SVG 이식 누락 3건, (c) radius 토큰 오선택 1건 — 즉 **구조가 아니라 토큰·에셋 수준의 마감 문제**다. 다만 batch2 가 다루지 않은 **상태 분기(정원마감 CTA, WaitlistModal, 운영중단 배너)** 는 여전히 통째로 비어 있어, 이 화면의 남은 작업량 대부분은 여기 있다.

## 8. 사용자 결정 필요
