오픈 D-N — 만들지 않는다
지적하신 그대로다. 마감 D-day 는 기준이 하나다 — endDate 는 프로그램 정보에 이미 확정돼 있고, 등록이 언제 됐든 남은 날짜는 같다. 반면 오픈 D-N 은 세기 시작하는 시점이 등록 시점에 달려 있다. 3주 전에 등록된 프로그램은 D-14 부터 카운트다운이 보이고, 시작 이틀 전에 등록된 프로그램은 D-2 에 갑자기 나타난다. 같은 화면에서 같은 칩이 서로 다른 것을 뜻하게 된다.

그래서 8/28 오픈 날짜 텍스트만 쓴다. ProgramCardDto.secondaryLabel 에 이미 있는 값이라 서버에 새로 만들 것이 없다.
마감임박 — 구분하지 않는다
이것도 맞다. 마감임박은 모집중의 하위 구간이지 별개 상태가 아니다. 상태 탭에도 없다 — 탭에서 "모집중"을 고른 사람에게 셀 색이 갈리면, 필터 결과 안에서 뭔가 다른 부류가 섞인 것처럼 읽힌다.

시급성은 이미 두 곳이 맡고 있다: 우측 패널·카드의 DdayChip(D-3 이하 빨강)과 CapacityBar(≥90% error). 둘 다 그 프로그램을 이미 들여다보는 중일 때 나온다 — 캘린더 셀을 훑는 단계에서 필요한 정보가 아니다. 서버 임계값은 손대지 않는다.
남는 결과 — 캘린더가 임계값을 하나도 쓰지 않는다
셀 색은 getStatus() 가 startDate · endDate 두 날짜로 내는 값 그대로다. 신청률 70/90%, D-3, D-14 — 어느 것도 캘린더에 들어오지 않는다. 범례 = 상태 탭 = 서버 enum 이 같은 3개가 되고, 새로 문서화할 임계값도 없다. 결과적으로 3a 를 택한 셈이고, 3b(마감일 축에서만 빨강)도 함께 접었다 — 축마다 범례가 바뀌는 편이 얻는 것보다 설명 비용이 크다.

3마감임박을 캘린더 색으로 둘 것인가

결론부터 — 빼는 게 맞다. 단, 마감일 축에서는 되살린다.
① 마감임박은 상태가 아니다. 상태축(진행예정 · 모집중 · 종료)과 시급성축(D-3, 신청률 90%)은 성격이 다른데, 한 색 스케일에 섞으면 범례가 두 종류를 한 줄에 늘어놓게 된다. 공공 신청 서비스(서울시 공공서비스예약 · 온통청년 · 지자체 청년센터)가 예외 없이 상태 뱃지와 D-day를 따로 두는 이유다.
② 이 제품에는 이미 시급성 채널이 둘 있다. DdayChip(D-3 이하 → error 배경, tsx L257)과 CapacityBar(신청률 ≥90% → error, ProgramCardDto.colorClass). 캘린더 점까지 쓰면 같은 신호를 세 곳에서 말한다.
③ 상태 탭과 범례가 어긋난다. 탭은 전체 · 모집중 · 진행예정 · 종료 3상태다. "모집중" 탭으로 걸러 들어왔는데 셀에 파랑과 빨강이 섞여 있으면, 같은 탭에 속한 것들이 다른 것처럼 읽힌다.
